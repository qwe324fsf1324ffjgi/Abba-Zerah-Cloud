## 🧠 My RPI Method: Research. Plan. Implement.

I call my workflow **RPI — Research, Plan, Implement.**

It is how I structure AI-assisted engineering to reduce wasted effort, expose risks earlier, and make progress more deliberate.

### 01 — Research before touching the code

I investigate the existing system, requirements, dependencies, failure modes, constraints, and available evidence.

I use AI to help explore unfamiliar concepts, inspect code, compare approaches, identify edge cases, and challenge assumptions.

The objective is not to get an answer quickly. It is to understand the problem well enough to choose a defensible solution.

### 02 — Plan before making changes

Before implementation, I want a clear picture of:

* What needs to change and why.
* What must remain untouched.
* Security and reliability implications.
* How success will be measured.
* What tests and validation gates are required.
* How to recover if the change fails.

This makes AI-assisted work more controlled and reduces unnecessary rework.

### 03 — Implement with AI, engineering judgment, and guardrails

I use AI coding assistance to accelerate research, implementation, documentation, debugging, and repetitive engineering tasks.

But generated code is a proposal, not proof of correctness.

I use review, automated tests, security checks, Git history, and explicit verification to build confidence in the result.

### 04 — Verify what actually happened

A successful command is not the same as a successful system.

I care about test results, deployment status, infrastructure state, permissions, logs, recovery procedures, and whether the intended outcome was achieved.

### 05 — Capture the lesson and improve the process

I document decisions, mistakes, trade-offs, and reusable procedures so the next task becomes easier.

**The advantage I am pursuing is not simply typing faster with AI. It is reducing the time between understanding a problem and delivering a verified, maintainable solution.**

## 🤖 AI Is Part of My Engineering Workflow

AI is changing how quickly engineers can explore ideas, write code, debug problems, and automate repetitive work.

But it also introduces new risks: incorrect assumptions, insecure code, hidden regressions, overconfidence, and changes that appear successful without being properly validated.

I want to become the engineer who can use AI productively without surrendering engineering judgment.

My AI-assisted workflow focuses on:

* Researching unfamiliar systems before implementation.
* Breaking large tasks into smaller, reviewable changes.
* Using AI to explore alternatives and identify edge cases.
* Automating repetitive work where automation is appropriate.
* Running tests and independent checks rather than trusting generated output.
* Reviewing security, permissions, deployment effects, and rollback options.
* Keeping meaningful changes in version control.
* Documenting decisions so other engineers can understand the work.

My measure of AI productivity is not how much code I generate.

It is how much **verified engineering progress** I can make without sacrificing security, maintainability, or reliability.
